## 摘要（Abstract）

我们提出 Cosmos 3，一个全模态（omnimodal）世界模型家族，能够在统一的混合 Transformer（mixture-of-transformers, MoT）架构中联合处理并生成语言、图像、视频、音频与动作序列。通过支持高度灵活的输入-输出配置，Cosmos 3 无缝统一了物理 AI（Physical AI）所必需的若干关键模态——实际上把视觉-语言模型、视频生成模型、世界仿真器与世界-动作模型收束进单一框架。我们的评测表明，Cosmos 3 在多样化的理解与生成任务上均建立了新的最先进（state-of-the-art）水平，论证了全模态世界模型可作为具身智能体的可扩展通用骨干。我们的后训练 Cosmos 3 模型在技术报告撰写之时，被 Artificial Analysis 评为最佳的开源文生图与图生视频模型，并被 RoboArena 评为最佳策略模型。为推动物理 AI 的开放研究与部署，我们在 Linux 基金会的 OpenMDW-1.1 许可证下，于 github.com/nvidia/cosmos 与 huggingface.co/collections/nvidia/cosmos3 公开代码、模型权重、合成的精选数据集以及评测基准。项目网站为 research.nvidia.com/labs/cosmos-lab/cosmos3。

## 1. 引言（Introduction）

物理 AI 智能体感知、推理并采取行动以与真实世界交互。然而，直接在真实世界中训练这类智能体是缓慢、昂贵且可能危险的。为克服这些瓶颈，我们必须构建一个训练设施，使安全、可扩展的学习能在仿真世界中进行，让物理 AI 智能体在其中获得两种根本耦合的能力：**理解**与**生成**。理解使智能体能够从残缺观测中推断隐表示、语义与动力学；生成则使智能体能够预测并仿真合理的未来，预判世界如何演化以及智能体应如何相应地采取行动。已有工作大多孤立地对待这两大支柱，导致感知与推理使用分离的判别式模型（如视觉-语言模型 VLM）、世界仿真使用生成式模型（如视频生成模型与前向动力学模型）、动作预测另用一类模型（如视觉-语言-动作模型 VLA 与世界-动作模型 WAM）。

我们认为这种范式割裂从根本上构成限制：理解需要就世界的未来演化与行为后果进行推理，而生成依赖于世界与智能体行为的紧凑、结构化表示。因此，把两者统一进一个可扩展的框架对物理 AI 而言是必不可少的。设想一台通用家庭机器人被要求晚餐后清理餐桌：在现有范式下，它必须拼凑一套彼此割裂的模型——用 VLM 定位餐具并生成可执行计划，用 VLA 或 WAM 生成动作序列，再用前向动力学模型或"世界模型"来仿真并评估未来状态。这种碎片化架构是次优且计算浪费的。我们能否转而设计单一模型，原生地覆盖物理 AI 智能体所需的全部关键能力？

我们提出 Cosmos 3，一个全模态世界模型家族，联合建模语言、图像、视频、音频与动作，同时服务于理解与生成。作为物理 AI 的通用骨干，Cosmos 3 在单一框架内统一了大量彼此不同的模型类别（图 1）。依据输入-输出配置的不同，Cosmos 3 可在多种运行模式之间无缝切换：它可作为多模态理解与推理的视觉-语言模型；可作为文生图模型；可作为视频生成器，用于文本生成视频、图像动画（图生视频）、未来预测（视频生视频）或同步的音视频生成；也可作为世界-动作模型，联合预测动作与环境仿真。通过在无需架构改动的前提下统一感知、仿真与执行，Cosmos 3 消除了碎片化、任务专用管线的需要，使通过共享表示与联合多任务监督实现的可扩展学习成为可能。

## 2. 模型架构（Model Architecture）

Cosmos 3 能够处理多模态输入并生成多模态输出。除语言、视觉（图像与视频）、音频之外，Cosmos 3 把**动作**视为一等模态，引入专门的**动作 token** 类。这些动作 token 把物理世界与基于语言的推理、基于视频的世界建模连接起来，直接链接到物理接地的控制信号以实现真实世界交互。Cosmos 3 集成模态专用编码器，将不同模态投影进统一的表示空间，随后由混合 Transformer（MoT）骨干处理。推理时，语言 token 通过下一 token 预测生成，其余模态通过迭代去噪生成。

### 2.1 编码器（Encoders）

给定由语言、视觉、音频与动作组成的输入序列，第一步是用模态专用编码器把它们嵌入统一的表示空间。为使共享的 Transformer 参数与位置嵌入能够区分不同模态，我们在送入 MoT 骨干之前，为每个非语言模态加上一个可学习的、模态特定的嵌入向量。

#### 2.1.1 图像与视频

对视觉输入我们采用两个独立编码器。视觉**理解**使用一个经视觉-语言对齐预训练的 ViT 编码器；视觉**生成**使用 Wan2.2-TI2V-5B 的视频 VAE 编码器（Wan et al., 2025a）。ViT 编码器的 patch 尺寸为 16×16，其后接一个两层 MLP，用于合并 2×2 的 token 并把它们投影到 Transformer 的隐空间。遵循 Qwen3-VL（Bai et al., 2025b），我们还通过 DeepStack（Meng et al., 2024）聚合来自 ViT 的视觉特征，并在视频帧之间交错插入文本化的视频时间戳（Chen et al., 2024b）。VAE 编码器对输入视频做 4× 时间压缩与 32×32 空间压缩，具体实现为先 16×16 空间压缩再接 2×2 patch merge。我们用一个线性层把每个 VAE token 投影到 Transformer 的隐维度，然后送入 MoT 骨干。用于理解的 ViT 编码器与骨干联合训练，而用于生成的 VAE 编码器在训练期间保持冻结。

#### 2.1.2 音频

对音频生成，我们采用 Lee et al. (2025b) 的音频 VAE 架构。采样率 48 kHz 的原始立体声以 1920 样本的跳步（hop size）编码，得到每秒音频 25 个 token。音频 VAE 在训练期间冻结。与其他非文本模态一样，音频 token 在进入 MoT 骨干前用一个线性层投影到 Transformer 的隐维度。

#### 2.1.3 动作

我们支持多种本体形态的动作建模，包括自动驾驶汽车、相机运动、机器人与人称第一视角运动（头部与手部）。由于每个域都有其原生的控制空间——例如关节轨迹、转向指令、身体姿态或相机变换——我们把它们映射进统一的动作接口，从而在不同域之间实现一致的多模态推理、生成与策略学习。

> **图 3**：统一动作表示。我们把异构本体控制映射为由共享几何分量构成的紧凑动作向量。自我（ego）与执行器（effector）运动被编码为相对位姿伪动作，使用 3D 平移 + 6D 旋转（旋转自由度为 3 时的过参数化表示，Zhou et al., 2019）；抓取状态则直接编码当前的操作状态，例如手部的指尖位置或机器人的夹爪开合值。域感知的输入与输出投影处理长度各异的动作向量，同时保持共享的语义空间。
>
> 图中各本体的维度构成：自动驾驶 9D（自我位姿）；相机运动 9D；第一人称运动 57D（9D + 9D + 15D + 9D + 15D，即头部位姿 + 左右执行器位姿 + 各手抓取状态）；单臂机器人 10D（9D + 1D）；双臂机器人 20D（9D + 1D + 9D + 1D）；人形机器人 29D。

**动作表示。** 我们用动作表示引发世界状态变化的因果变量。给定连续的视觉 token，动作 token $a_t$ 表示从前一状态 $v_{t-1}$ 到当前状态 $v_t$ 的转移。每个数据源被转换为捕获不同动作域之间共享底层几何结构的紧凑表示，如图 3 所示。在高层面上，动作最多包含三个分量：智能体主要观测框架的**自我位姿**（ego pose）、智能体执行器的**执行器位姿**（effector pose），以及表征操作状态的**抓取状态**（grasp state）。为避免依赖具体本体控制器的细节（如 PID 参数或低层驱动接口），自我位姿与执行器位姿由状态差分得到的**伪动作**表示。对连续的 SE(3) 位姿 $T_{t-1}$ 与 $T_t$，我们把它表示为相对变换 $\Delta T = T_{t-1}^{-1} T_t$。旋转遵循 Zhou et al. (2019) 的 6D 表示与 OpenCV 约定（z 轴沿手指/夹爪方向，x 轴向右）。抓取状态的处理不同：它不表示时间差分，而是直接编码时刻 $t$ 的当前操作状态。

对相机与自动驾驶汽车，动作仅由自我位姿表示，不含执行器位姿与抓取状态。对第一视角数据，我们用头部相机位姿增量作为自我位姿、腕部位姿增量作为执行器位姿、各腕坐标系下的指尖位置作为抓取状态（Yang et al., 2025d）。对机器人数据，我们用头部相机位姿增量作为自我位姿、末端法兰位姿增量作为执行器位姿（Lyu et al., 2026）、连续的开合值作为抓取状态。

**动作 token 化。** 我们的动作表示在保留本体特定结构与语义的同时，把多样本体映射进共享的隐动作空间。因此我们使用域感知的输入与输出投影层，为每个本体域设置独立权重矩阵（Zheng et al., 2026），同时共享 MoT 骨干。对输入 $x \in \mathbb{R}^{in_d}$——例如拼接头部位姿增量、左右腕位姿增量与指尖坐标的第一视角动作向量——以及域标识符 $d \in \{1, \dots, N\}$，输入投影为：

$$z = W^{in}_{(d)} x + b^{in}_{(d)} \tag{1}$$

其中 $z \in \mathbb{R}^{d_{model}}$ 是隐动作 token，$x$ 为归一化后的动作向量，$W^{in}_{(d)}$ 与 $b^{in}_{(d)} \in \mathbb{R}^{d_{model}}$ 是域特定的输入投影矩阵与偏置。为把 token 解码回原始动作空间，我们使用域特定的输出投影：

$$\hat{x} = W^{out}_{(d)} z + b^{out}_{(d)} \tag{2}$$

其中 $W^{out}_{(d)} \in \mathbb{R}^{in_d \times d_{model}}$、$b^{out}_{(d)} \in \mathbb{R}^{in_d}$ 是域特定的输出投影矩阵与偏置。所有投影参数均从零初始化，并与 MoT 骨干联合优化。我们用奇异值分解（SVD）把预测的 6D 旋转转回 $3\times3$ 的 SO(3) 旋转矩阵。

### 2.2 Token 排布与生成模式（Token Arrangement and Generation Mode）

Cosmos 3 是一个统一模型，支持多种模态与任务。不同任务可形式化为交错的多模态序列，每个序列由来自不同模态的若干片段（segment）组成。给定任务后，所有片段先由模态专用编码器嵌入为表示。嵌入之后，来自不同模态的 token 按适用于所有任务的统一格式打包，下面逐一说明。

#### 2.2.1 Token 排布

输入 token 序列由两个子序列组成：先自回归（AR）子序列，后扩散（DM）子序列。

**AR 子序列**负责推理与理解，包含语言 token 以及由 ViT 编码器嵌入的视频与图像 token。所有 AR token 被路由到 Transformer 解码器层中一组专用参数。

**扩散子序列**跟随在 AR 子序列之后，包含来自 VAE 编码器的视频与图像 token，以及音频与动作 token。生成时，模型对带噪扩散 token 迭代去噪以产生相应的干净 token。扩散 token 被路由到与 AR token 不同的一组参数，同时在每个 Transformer 解码器层中通过联合注意力与 AR token 交互。

对任何给定任务，我们都用同一格式排列这些 token：(1) 自回归 token 置于扩散 token 之前；(2) 在扩散子序列内部，对每个模态，干净的条件 token 排在带噪扩散 token 之前；(3) 在条件子序列与扩散子序列内部，token 均按视觉、音频、动作的模态顺序排列。借助这一统一格式，Cosmos 3 可支持下述各种生成任务。

#### 2.2.2 生成模式

Cosmos 3 支持语言、视觉、音频、动作四类模态。我们把干净的视觉、音频、动作 token 记为 $v, s, a$，其带噪对应物加波浪号记为 $\tilde v, \tilde s, \tilde a$。据此，所支持的生成模式如下。

- **语言。** 生成语言时输入只含自回归子序列，生成专用的扩散参数不被激活。若存在图像与视频输入，它们由 ViT 编码器嵌入并放入 AR 子序列。在此设定下 Cosmos 3 如同一个标准 VLM 运行。

- **文生图（Text-to-Image）。** AR 子序列含语言 token，扩散子序列含由 VAE 编码器嵌入的带噪目标图像 token。整个 token 序列为：

$$S_{T2I} = [S_{AR}, \tilde v_1] \tag{3}$$

其中 $S_{AR} = [x_1, \dots, x_n, \mathrm{EOS}, \mathrm{BOG}]$ 是下列所有模式共享的 AR 前缀（$x_1,\dots,x_n$ 为语言 token，EOS 与 BOG 分别为句尾与生成起始特殊 token），$\tilde v_1$ 为带噪图像 token。

- **文生视频（+音频）。** 与文生图类似，但扩散子序列含带噪的目标视频 token。当同时（可选地）生成音频时，带噪音频 token 追加在带噪视觉 token 之后。总体上：

$$S_{\text{T2V+Audio}} = [S_{AR}, \tilde v_{1:F}, \tilde s] \tag{4}$$

其中 $F$ 为隐视频帧数。

- **图生视频 / 视频生视频（+音频）。** 该模式引入一张初始条件图像或若干初始视频帧，模型据此与文本提示生成完整续接。在扩散子序列中，干净的条件图像或视频 token 排在带噪目标视频 token 之前：

$$S_{V2V} = [S_{AR}, v_{1:k}, \tilde v_{k+1:F}] \tag{5}$$

其中 $k$ 为条件隐帧数。当 $k = 1$ 时任务为图生视频，$k > 1$ 对应视频生视频。若同时生成音频，音频 token 的追加方式与文生视频相同。

- **视频转换（Video transfer）。** 该任务的输入是一段控制视频（例如边缘图或深度图）加一段文本描述，模型生成对应的 RGB 视频。token 布局与视频生视频类似，把控制视频 token 作为条件 token、RGB 视频 token 作为带噪目标 token：

$$S_{\text{Transfer}} = [S_{AR}, v^{ctrl}_{1:F}, \tilde v_{1:F}] \tag{6}$$

其中 $v^{ctrl}_{1:F}$ 是控制视频经 VAE 编码后的干净 token。

- **动作。** Cosmos 3 支持三种动作生成模式——前向动力学、逆向动力学，以及视频-动作联合预测（策略）。对一段含连续视觉 token 的轨迹，每个动作 token $a_t$ 表示 $v_{t-1}$ 到 $v_t$ 的转移。前向动力学在观测上下文与干净动作 token 条件下预测未来视觉状态；逆向动力学推断能够解释所见视觉变化的动作 token；策略模式下模型联合预测动作与视觉 token，从而在同一个序列模型中同时生成干预动作与其预期视觉后果。条件方向总结于图 4。

> **图 4**：动作序列配置。对一条视频-动作数据样本，Cosmos 3 通过改变哪些 token 是干净的、哪些是带噪的来构造不同的训练模式。图中展示一个局部时间窗口，其中动作 token 位于相邻视觉 token 之间：$a_t$ 连接 $v_{t-1}$ 与 $v_t$，$a_{t+1}$ 连接 $v_t$ 与 $v_{t+1}$。前向动力学模式在干净动作 token 条件下对视觉 token 去噪；逆向动力学模式在干净视觉 token 条件下对动作 token 去噪；视频-动作（策略）模式对视觉与动作 token 同时去噪。为简洁省略语言与特殊 token。

### 2.3 混合 Transformer（MoT）架构

Cosmos 3 采用混合 Transformer（MoT）架构，处理来自不同模态 token 组成的统一序列。在层级上，每个 Transformer 解码器层包含两组参数：一组处理来自 AR 子序列的 token，用于**推理**任务；另一组处理来自扩散子序列的 token，用于**生成**任务。尽管 Cosmos 3 与 Deng et al. (2025) 等统一生成模型在解码器层结构上有相似之处，但它在训练策略、位置嵌入以及整体能力上均有所不同。

#### 2.3.1 双塔层结构

标准 Transformer 解码器层由自注意力、前馈网络与若干归一化层构成。MoT 设计并非对所有 token 类型使用同一组参数，而是使用两条通路，如图 5 所示。每条通路都是一个标准 Transformer 层，拥有自己的参数，包括层归一化模块、注意力投影矩阵与前馈网络。两条通路的权重都从同一个预训练视觉-语言模型（VLM）初始化，使 Cosmos 3 在学习生成高保真视频的同时继承强大的语言与视觉推理能力。在训练与推理时，位于前部的 AR 子序列都被路由到推理器塔（reasoner tower），后部的扩散子序列被路由到生成器塔（generator tower）。

> **图 5**：Cosmos 3 的混合 Transformer（MoT）架构。左：单一 Transformer 作用于一条包含 AR 与扩散两个子序列的 token 序列。AR 段承载离散文本 token 以及可选的 ViT 编码视觉 token，以 `<EOS>` 与生成起始 token `<BOG>` 结尾；DM 段承载来自各自编码器的连续 token，训练时被加噪扰动。此处为简便起见把所有输入 token 都画成带噪——在图生视频、视频转换等生成模式中，干净的条件 token 会排在 DM 中带噪目标之前（见 §2.2.2）。在每个 Transformer 块内，AR token 与 DM token 由相互独立的 LayerNorm 与 MLP 处理（两者均从预训练 VLM 共同初始化），仅在共享的自注意力算子处相遇。以 $Q,K,V$ 表示注意力的查询、键、值向量，下标标明其所属塔：$Q_{AR}$ 仅对 $K_{AR}, V_{AR}$ 做因果注意力；$Q_{DM}$ 对拼接后的 $[K_{AR};K_{DM}]$ 与 $[V_{AR};V_{DM}]$ 做全注意力。如此，扩散以 AR 上下文为条件，而 AR 保持自回归自洽。输出对推理器而言是下一 token 预测，对生成器而言是去噪 token（实际训练使用 flow-matching 目标、预测速度；图中为清晰起见画出干净目标）。右：注意力掩码——AR 为因果，扩散为全注意力。

#### 2.3.2 双流联合注意力

尽管两塔使用独立参数，扩散子序列的 token 仍通过一个双流联合注意力操作与 AR 子序列交互。我们把 AR 与扩散子序列的查询、键、值向量分别记为 $Q_{AR}, K_{AR}, V_{AR}$ 与 $Q_{DM}, K_{DM}, V_{DM}$。

**AR 子序列的注意力。** AR 子序列中的 token 只以因果自注意力关注 AR 子序列内部的 token；即每个 token 只能看到同一序列中在它之前的 token。这与从 VLM 骨干继承的自回归性质完全一致，使模型得以保留预训练 VLM 的文本生成能力：

$$O^{(l)}_{AR} = \mathrm{Attn}_{\mathrm{causal}}\big(Q_{AR}, K_{AR}, V_{AR}\big) \tag{7}$$

**扩散子序列的注意力。** DM 子序列中的 token 使用全双向注意力，并以 AR 与 DM token 的并集作为键与值。这使每个扩散 token 都能自由关注来自 AR 子序列的文本提示，以及序列中所有其他条件与扩散 token，从而维持时空一致性：

$$O^{(l)}_{DM} = \mathrm{Attn}_{\mathrm{full}}\Big(Q_{DM},\,[K_{AR}; K_{DM}],\,[V_{AR}; V_{DM}]\Big) \tag{8}$$

其中 $[\cdot\,;\cdot]$ 表示沿序列维度拼接。注意，AR token 从不依据 DM token 被更新，从而保持条件通路因果完整性。

### 2.4 多模态位置嵌入

位置嵌入把时间与空间结构注入注意力机制，促使 token 更强烈地关注语义与几何相关的 token——通常在空间或时间上邻近。由于 Cosmos 3 在统一注意力框架内联合建模语言、视觉、音频与动作 token，设计一套能跨模态一致泛化的位置嵌入本质上具有挑战。受 3D 多模态 RoPE（MRoPE）（Bai et al., 2025a）启发，我们设计了带绝对时间索引的 3D MRoPE，把视频、音频与动作 token 对齐到同一物理时间轴上。原始 3D MRoPE 把每个注意力头的隐维度分成时间、高、宽三个分量，其中时间分量只记录离散 token 序号。这对图像与视频理解任务足够，但在我们的设定下并不充分：视频、音频与动作 token 可能以不同的帧率或采样率同时生成，此时不同模态的 token 必须对齐到一条绝对物理时间轴。我们先给出与原始 3D MRoPE 一致的基础形式，再说明我们的扩展与改动，尤其是对齐绝对时间轴的绝对时间调制。

#### 2.4.1 位置索引分配

**自回归 token。** 为与语言生成及图像/视频理解模型向后兼容，AR 子序列中所有语言 token 与 ViT 编码媒体 token 的位置索引沿用原始 3D MRoPE 设计。语言 token 令 $t = h = w$ 取同一个单调递增值，使 3D MRoPE 退化为标准 1D RoPE 行为。ViT 编码 token 由同一帧的所有 token 共享 $t$，而 $h$ 与 $w$ 依各 token 的空间位置独立变化。AR 子序列中的位置索引分配与 Qwen3-VL（Bai et al., 2025a）的 3D MRoPE 完全一致。

**扩散 token。** 如图 6 所示，视频 token 在三个轴上都变化：$t$ 随时间隐帧索引推进，$h$ 与 $w$ 在每帧内按空间网格（$0\dots H-1$、$0\dots W-1$）铺展。图像 token 被当作单帧视频处理，仅在 $(h, w)$ 上变化。空间与时间索引都在每个视觉片段开始时重置为零，因此模型把 $t, h, w$ 视为**视频内的绝对坐标**，而非全局序列中的位置。举例说，在视频转换任务中，用户给出文本提示与控制视频帧（如深度图），则干净的控制视频 token 与带噪生成视频 token 都从 AR 子序列最后一个 token 的时间偏移开始。所有音频与动作 token 只携带时间坐标，空间索引置零（$h = w = 0$）：音频 token 的时间索引随每个音频跳步推进，动作 token 的时间索引随每个采样步推进。

**AR 与扩散 token 之间的间隔。** 实践中我们发现，直接让扩散 token 从最后一个 AR token 的时间偏移接续，会导致初始视频帧出现过饱和与棋盘格伪影；这一现象在更大规模的变体（如 Super 模型）上尤为明显。我们推测其原因是最后一个语言 token 与第一帧的视觉 token 占据相邻的时间位置，导致时间嵌入几乎相同。为此，受 Cao et al. (2025) 启发，我们在 AR 与扩散子序列之间插入一个**固定时间间隔**，把其后所有视觉、音频、动作 token 的时间索引整体平移，从而在位置空间中形成一个缓冲，提供清晰的文本到视觉过渡信号，而不需架构改动或额外的可学习嵌入。所有模型中该间隔设为 **15000**。

> **图 6**：3D MRoPE 下的坐标分配示意。左：一条打包序列，含语言、视频（两帧，每帧 2×2 空间网格）、音频与动作 token，每个 token 获得一个 $(t,h,w)$ 三元组。语言 token 使用 $t=h=w$；视频 token 三轴皆变；音频与动作 token 仅取时间坐标（$h=w=0$）；模态偏移 $\Delta$ 分隔文本与视觉的时间区间。右：FPS 调制把帧索引映射为缩放后的时间位置，使得在 16、24、30 FPS 下相等的真实世界时长占据相等的位置区间，其中 24 FPS 为基准。时间位置的间距反映真实世界时间，而非 token 计数。

#### 2.4.2 绝对时间调制

沿时间维度一个单位步长，在不同模态或不同数据源之间可能对应不同的物理时间间隔。例如以 60 FPS 与 24 FPS 编码视频时，24 FPS 视频 token 的一次时间索引递增所对应的物理时长，是 60 FPS 情形的 2.5 倍。类似差异也出现在音频与动作 token 上，因为不同数据源采样率不同。FPS 调制的作用就是通过调节每个时间增量的有效尺度，把不同时间分辨率的 token 对齐到共享的物理时间轴。

我们先定义**每秒时间步数**（temporal steps per second, TPS）来刻画物理时间分辨率。对视频 token，TPS 等于视频帧率除以时间压缩因子（因视频 VAE 编码器而为 4）。对音频 token，$\mathrm{TPS}_{\text{audio}} = 48000 / 1920 = 25$。对动作 token，TPS 恰为动作数据的采样频率。

我们把沿时间维的单位长度与一个基准 TPS 相关联，记作 $\mathrm{TPS}_{\text{base}}$。对给定扩散子序列中的 token，先计算其对应的 TPS。当时间索引需要增加一个单位步长时，带调制的真实时间增量 $\Delta$ 按下式计算：

$$\Delta = \mathrm{TPS}_{\text{base}} / \mathrm{TPS} \tag{9}$$

由于视频在训练数据中占多数，且 24 FPS 是我们设定中最常见的帧率，因此取 $\mathrm{TPS}_{\text{base}} = 24/4 = 6$，其中 4 为视频 tokenizer 的时间压缩比。

### 2.5 模型变体（Model Variants）

Cosmos 3 在三个规模上训练：Edge、Nano 与 Super，覆盖从端侧部署到大规模数据中心推理的宽计算预算区间。Edge 是一个 40 亿参数模型，构建在一个稠密 20 亿参数的 Transformer 之上；Nano 是 160 亿参数模型，构建在稠密 80 亿参数 Transformer 之上；Super 是 640 亿参数模型，构建在稠密 320 亿参数 Transformer 之上。所有变体都从预训练的视觉-语言模型初始化，并采用上文所述 MoT 架构。表 2 汇总各变体的关键架构超参。本文发布 Cosmos3-Nano 与 Cosmos3-Super，Cosmos3-Edge 将在后续版本发布。⟨注：Edge 实际已于 2026 年 9 月 16 日在 Hugging Face 公开发布，非受限访问；见 `staging/Cosmos3-Edge/`。⟩

**Cosmos3-Edge** 采用 20 亿稠密 Transformer 设计：28 层、隐维度 2048、16 个注意力头、8 个键值头、头维度 128、FFN 维度 9216。我们用 Megatron 代码库从零训练该 LLM。其 LLM 设计大体遵循 Qwen3-1.7B，有两点显著差异：去掉 QK 归一化，并使用 ReLU 平方（ReLU-squared）作为 FFN 激活，与表 2 报告的 Edge FFN 维度配套。

**Cosmos3-Nano** 适配 Qwen3-VL 8B（Bai et al., 2025b）架构：LLM 36 层、隐维度 4096、32 个注意力头、8 个键值头、头维度 128、FFN 维度 12288。

**Cosmos3-Super** 适配 Qwen3-VL 32B（Bai et al., 2025b）架构：LLM 64 层、隐维度 5120、64 个注意力头、8 个键值头、头维度 128、FFN 维度 25600。
