# 2 模型架构

Cosmos 3 能够处理多模态输入并生成多模态输出。除语言、视觉（图像与视频）、音频之外，Cosmos 3 把动作（action）视为一个核心模态，并引入专门的一类动作 token。这些动作 token 把物理世界与基于语言的推理、基于视频的世界建模桥接起来，直接连接到物理接地的控制信号以用于真实世界交互。Cosmos 3 集成模态专用编码器，把不同模态投影进一个统一的表示空间，随后由混合 Transformer（MoT）骨干进行处理。在推理时，语言 token 通过下一 token 预测生成，而其余模态通过迭代去噪生成。

## 2.1 编码器

给定一个由语言、视觉、音频与动作组成的输入序列，第一步是使用模态专用编码器把它们嵌入到一个统一的表示空间中。为使共享的 Transformer 参数与位置嵌入能够区分不同模态，我们在把每个非语言模态送入 MoT 骨干之前，为其加上一个可学习的、模态特定的嵌入向量。

### 2.1.1 图像与视频

对视觉输入我们采用两个相互独立的编码器。对于视觉理解，我们使用一个经视觉-语言对齐预训练的 ViT 编码器。对于视觉生成，我们使用 Wan2.2-TI2V-5B(Wan et al., 2025a)的视频 VAE 编码器。ViT 编码器的 patch 尺寸为 $16\times 16$，其后接一个两层 MLP，用于合并 $2\times 2$ 的 token 并把它们投影到 Transformer 的隐空间中。遵循 Qwen3-VL(Bai et al., 2025b)，我们还通过 DeepStack(Meng et al., 2024)从 ViT 聚合视觉特征，并在视频帧之间交错插入文本化的视频时间戳(Chen et al., 2024b)。VAE 把输入视频在时间上压缩 $4\times$、在空间上压缩 $32\times 32$，具体实现为先做 $16\times 16$ 的空间压缩，再做 $2\times 2$ 的 patch merge。我们使用一个线性层把每个 VAE token 投影到 Transformer 的隐维度，然后再把隐变量送入 MoT 骨干。用于理解的 ViT 编码器与骨干联合训练，而用于生成的 VAE 编码器在训练期间保持冻结。

### 2.1.2 音频

对于音频生成，我们采用 Lee et al. (2025b) 的音频 VAE 架构。以 48 kHz 采样的原始立体声音频用 1920 样本的跳步（hop size）进行编码，得到每秒音频 25 个 token。音频 VAE 在训练期间保持冻结。与其余非文本模态一样，音频 token 在进入 MoT 骨干之前，用一个线性层投影到 Transformer 的隐维度。

### 2.1.3 动作

我们支持跨多种本体形态的动作建模，包括自动驾驶汽车、相机运动、机器人以及第一人称人体运动（头部与手部）。由于每个域都暴露其自身的原生控制空间——例如关节轨迹、转向指令、身体位姿或相机变换——我们把它们映射到一个统一的动作接口之中，从而在不同域之间实现一致的多模态推理、生成与策略学习。

#### 动作表示。

我们用动作来表示引发世界状态变化的因果变量。给定连续的视觉 token，动作 token $a_{t}$ 表示从前一状态 $v_{t{-}1}$ 到当前状态 $v_{t}$ 的转移。每个本体数据源都被转换为一种紧凑表示，用以捕获不同动作域之间共享的底层几何结构，如图 3 所示。在较高层面，动作最多可包含三个分量：用于智能体主要观测帧的自我位姿（ego pose）、用于智能体执行器的执行器位姿（effector pose），以及用于表征操作状态的抓取状态（grasp state）。为了避免涉及具体本体的控制器细节，例如比例-积分-微分（Proportional–Integral–Derivative, PID）参数或低层驱动接口，自我位姿与执行器位姿被表示为由状态差分导出的伪动作。对于连续的 $\mathrm{SE}(3)$ 位姿 $\mathbf{T}_{t-1}$ 与 $\mathbf{T}_{t}$，我们把运动表示为相对变换 $\Delta\mathbf{T}_{t}=\mathbf{T}_{t-1}^{-1}\mathbf{T}_{t}$。我们采用 Zhou et al. (2019) 的 6D 表示以及 OpenCV 的旋转约定，其中 z 轴沿手指/夹爪方向、x 轴指向右侧。抓取状态的处理方式则不同：它们不表示时间差分，而是直接编码时刻 t 的当前操作状态。

对于相机与自动驾驶汽车，动作仅由自我位姿表示，不含任何执行器位姿或抓取状态。对于第一人称数据，我们使用头部相机位姿增量作为自我位姿、腕部位姿增量作为执行器位姿，并把各腕坐标系中的指尖位置作为抓取状态(Yang et al., 2025d)。对于机器人数据，我们使用头部相机位姿增量作为自我位姿、末端执行器法兰位姿增量作为执行器位姿(Lyu et al., 2026)，并把连续的夹爪开/合值作为抓取状态。

![Figure 3](figures/tikz_action_representation.png)

> Figure 3: **统一动作表示。我们把异构的本体控制映射为由共享几何分量构成的紧凑动作向量。自我位姿与执行器位姿运动被编码为相对位姿伪动作，使用 3D 平移与 6D 旋转（Zhou Zhou et al. (2019) 提出的一种过参数化旋转表示，因为旋转的自由度为 3），而抓取状态直接编码当前的操作状态，例如手部的指尖位置或机器人的夹爪开/合值。域感知的输入与输出投影处理异质的动作向量长度，同时保持共享的语义空间。**

#### 动作 token 化。

我们的动作表示把多样本体映射进一个共享的隐动作空间，同时保留各本体特有的结构与语义。因此我们使用域感知的输入与输出投影层，为每个本体域设置独立的权重矩阵(Zheng et al., 2026)，同时共享 MoT 骨干。对于一个输入 $\mathbf{x}\in\mathbb{R}^{d_{\text{in}}^{(k)}}$——例如把头部位姿增量、左右腕位姿增量与指尖坐标拼接而成的第一人称动作向量——以及一个域标识符 $k\in\{1,\ldots,K\}$，输入投影为：

$$\mathbf{z}=\mathbf{W}_{\mathrm{in}}^{(k)}\mathbf{x}+\mathbf{b}_{\mathrm{in}}^{(k)}$$

其中 $\mathbf{z}\in\mathbb{R}^{d_{\text{model}}}$ 是隐动作 token，$\mathbf{x}$ 表示归一化后的动作向量，而 $\mathbf{W}_{\mathrm{in}}^{(k)}\in\mathbb{R}^{d_{\text{model}}\times d_{\text{in}}^{(k)}}$ 与 $\mathbf{b}_{\mathrm{in}}^{(k)}\in\mathbb{R}^{d_{\text{model}}}$ 是域特定的输入投影矩阵与偏置。

为把 token 解码回原始动作空间，我们使用一个域特定的输出投影：

$$\mathbf{x}=\mathbf{W}_{\mathrm{out}}^{(k)}\mathbf{z}+\mathbf{b}_{\mathrm{out}}^{(k)}$$

其中 $\mathbf{W}_{\mathrm{out}}^{(k)}\in\mathbb{R}^{d_{\text{in}}^{(k)}\times d_{\text{model}}}$ 与 $\mathbf{b}_{\mathrm{out}}^{(k)}\in\mathbb{R}^{d_{\text{in}}^{(k)}}$ 是域特定的输出投影矩阵与偏置。所有投影参数都从零开始初始化，并与 MoT 骨干联合优化。我们使用奇异值分解（SVD）把预测得到的 6D 旋转转换回一个 $3\times 3$ 的 $\mathrm{SO}(3)$ 旋转矩阵。

## 2.2 Token 排布与生成模式

Cosmos 3 是一个支持多种模态与多种任务的统一模型。不同任务可以被形式化为交错的多模态序列，每个序列由来自不同模态的一系列片段（segment）构成。给定一个任务后，所有片段先使用上述模态专用编码器被编码为嵌入。一旦被嵌入，来自不同模态的 token 会按照一种适用于所有任务的统一格式进行打包，我们接下来对此进行说明。

### 2.2.1 Token 排布

输入 token 序列由两个子序列组成：一个自回归（AR）子序列，其后跟着一个扩散（DM）子序列。

**AR 子序列**负责推理与理解。它包含语言 token，以及由 ViT 编码器嵌入的视频与图像 token。所有 AR token 都被路由到 Transformer 解码器层中一组专用的参数。

**扩散子序列**跟随在 AR 子序列之后，包含来自 VAE 编码器的视频与图像 token，以及音频与动作 token。在生成时，模型对带噪的扩散 token 进行迭代去噪，以产生相应的干净 token。扩散 token 被路由到一组与 AR token 所用参数相互分离的参数集，同时在每个 Transformer 解码器层中通过联合注意力与 AR token 发生交互。

对任何给定任务，我们都应用同一格式来排布这些 token：(1) 自回归 token 放在扩散 token 之前；(2) 在扩散子序列内部，对每个模态，干净的条件 token 放在带噪扩散 token 之前；(3) 在条件子序列与扩散子序列内部，token 均按视觉、音频、动作的模态顺序排列。借助这一统一格式，Cosmos 3 能够支持各种生成任务，我们在下文详述。

### 2.2.2 生成模式

Cosmos 3 支持不同模态：语言、视觉、音频与动作。我们把干净的视觉、音频与动作 token 分别记为 $v$、$s$ 与 $a$，并给它们的带噪对应物加上波浪号：$\tilde{v}$、$\tilde{s}$ 与 $\tilde{a}$。给定这些模态，所支持的生成模式列举如下：

- • **语言。** 对于语言生成，输入只包含自回归子序列，而生成专用的扩散参数不被激活。图像与视频输入（若存在）由 ViT 编码器嵌入并放入自回归子序列。在此设定下，Cosmos 3 的行为如同一个标准的 VLM。

- • **文生图（Text-to-Image）。** 在此模式中，自回归子序列包含语言 token，而扩散子序列包含由 VAE 编码器嵌入的带噪目标图像 token。整个 token 序列变为：$\mathbf{S}_{\mathrm{T2I}}=[\mathbf{S}_{\mathrm{AR}},\;\tilde{v}_{1}],$ (3) 其中 $\mathbf{S}_{\mathrm{AR}}\triangleq[l_{1},\ldots,l_{n},\langle\text{EOS}\rangle,\langle\text{BOG}\rangle]$ 是由下文所有模式共享的 AR 前缀（$l_{1},\ldots,l_{n}$ 是语言 token；$\langle\text{EOS}\rangle$ 与 $\langle\text{BOG}\rangle$ 分别是句末特殊 token 与生成起始特殊 token），而 $\tilde{v}_{1}$ 是带噪图像 token。

- • **文生视频（+音频）。** 此模式与文生图类似，但扩散子序列包含的是带噪的目标视频 token。当（可选地）联合生成音频时，带噪音频 token 被追加在带噪视觉 token 之后。综上，打包后的序列变为：$\mathbf{S}_{\mathrm{T2V+Audio}}=[\mathbf{S}_{\mathrm{AR}},\;\tilde{v}_{1:N},\;\tilde{s}],$ (4) 其中 $N$ 是隐视频帧的数量。

- • **图生视频/视频生视频（+音频）。** 此模式引入一张初始条件图像或若干初始视频帧，模型在它们以及文本提示的条件下生成完整的续接内容。在扩散子序列中，干净的条件图像或视频 token 之后跟着带噪的目标视频 token：$\mathbf{S}_{\mathrm{V2V}}=[\mathbf{S}_{\mathrm{AR}},\;v_{1:P},\;\tilde{v}_{P+1:N}],$ (5) 其中 $P$ 是条件隐帧的数量。当 $P=1$ 时任务变为图生视频，而 $P>1$ 对应视频生视频。当同时生成音频时，音频 token 的追加方式与文生视频情形相同。

- • **视频转换（Video transfer）。** 在此任务中，输入由一段控制视频（例如边缘或深度）加上一段文本描述构成，模型生成对应的 RGB 视频。其 token 布局与视频生视频类似，把控制视频 token 用作条件 token，把 RGB 视频 token 用作带噪目标 token：$\mathbf{S}_{\mathrm{Transfer}}=[\mathbf{S}_{\mathrm{AR}},\;v^{\mathrm{ctrl}}_{1:N},\;\tilde{v}_{1:N}],$ (6) 其中 $v^{\mathrm{ctrl}}_{1:N}$ 是控制视频经 VAE 编码后的干净 token。

- • **动作。** Cosmos 3 为动作支持三种生成模式——前向动力学、逆向动力学，以及视频-动作联合预测（策略）。对于一条含有连续视觉 token 的轨迹，每个动作 token $a_{t}$ 表示从 $v_{t{-}1}$ 到 $v_{t}$ 的转移。前向动力学在观测到的上下文与干净动作 token 的条件下预测未来的视觉状态，而逆向动力学推断能够解释所观测到的视觉变化的动作 token。在策略模式下，模型联合预测动作与视觉 token，使其能够在同一个序列模型中同时生成干预动作及其预期的视觉后果。条件方向总结于图 4。

## 2.3 混合 Transformer（MoT）架构

Cosmos 3 采用**混合 Transformer（MoT）**架构，处理由不同模态 token 构成的统一序列。在层级上，每个 Transformer 解码器层包含两组参数：一组用于推理任务，处理来自 AR 子序列的 token（推理器，reasoner）；另一组用于生成任务，处理来自扩散子序列的 token（生成器，generator）。尽管 Cosmos 3 在解码器层结构上与 Deng et al. (2025) 等统一生成模型有相似之处，但它在训练策略、位置嵌入以及整体能力上与之不同。

![Figure 5](figures/tikz_mot_architecture.svg)

> Figure 5: **Cosmos 3 的混合 Transformer（MoT）架构。** **左：** 单个 Transformer 作用于一条 token 序列，该序列由自回归（**AR** ）与扩散（**DM** ）两个子序列组成：AR 承载离散的文本 token 以及可选的 ViT 编码视觉 token，并以 <EOS> 和一个生成起始 token <BOG> 结尾；DM 承载来自各自编码器的连续 token，并在训练中被噪声扰动。此处为简便起见，我们把所有输入 token 都可视化为带噪的；对于图生视频或视频转换这类生成模式，干净的条件 token 会在 DM 中排在带噪目标之前；见 Sec. 2.2.2。在每个 Transformer 块内部，AR token 与 DM token 由相互独立的 LayerNorm 与 MLP 处理（二者均从预训练 VLM 共同初始化），并且仅在一个共享的自注意力算子处相遇。令 $\mathbf{Q}$、$\mathbf{K}$、$\mathbf{V}$ 为注意力中的查询、键、值向量，下标标明它处于哪一个塔中。$\mathbf{Q}_{\mathrm{AR}}$ 仅对 $\mathbf{K}_{\mathrm{AR}},\mathbf{V}_{\mathrm{AR}}$ 做因果注意力，而 $\mathbf{Q}_{\mathrm{DM}}$ 对拼接后的 $[\mathbf{K}_{\mathrm{AR}};\mathbf{K}_{\mathrm{DM}}]$ 与 $[\mathbf{V}_{\mathrm{AR}};\mathbf{V}_{\mathrm{DM}}]$ 做双向注意力。以这种方式，扩散以 AR 上下文为条件，而 AR 保持自回归上的自包含。输出对推理器而言是下一 token 预测，对生成器而言是去噪后的 token（实际训练中使用流匹配（flow-matching）目标来预测速度；为清晰起见，我们在此画出的是干净目标）。**右：** 注意力掩码，对 AR 为因果、对扩散为全注意力。

### 2.3.1 双塔层结构

一个标准的 Transformer 解码器层由一次自注意力操作、一个前馈网络以及若干归一化层构成。MoT 设计并不用同一组参数处理所有 token 类型，而是使用两条通路，如图 5 所示。每条通路都是一个拥有自身参数的标准 Transformer 层，包括 LayerNorm 模块、注意力投影矩阵以及前馈网络。两条通路都从一个预训练的视觉-语言模型（VLM）的权重初始化，使 Cosmos 3 在学习生成高保真视频的同时，继承较强的语言与视觉推理能力。无论在训练还是推理阶段，位于前部的 AR 子序列都被路由到推理器塔，而位于后部的扩散子序列被路由到生成器塔。

### 2.3.2 双流联合注意力

尽管两塔使用相互独立的参数，扩散子序列中的 token 仍通过一个双流联合注意力操作与 AR 子序列发生交互。此处我们把 AR 与扩散子序列的查询、键、值向量分别记为 $\mathbf{Q}_{\text{AR}}$、$\mathbf{K}_{\text{AR}}$、$\mathbf{V}_{\text{AR}}$、$\mathbf{Q}_{\text{DM}}$、$\mathbf{K}_{\text{DM}}$ 与 $\mathbf{V}_{\text{DM}}$。

#### 自回归子序列注意力。

AR 子序列中的 token 仅使用*因果自注意力（causal self-attention）*关注 AR 子序列内部的 token；也就是说，每个 token 只能关注同一序列中位于它之前的 token。这与从 VLM 骨干继承的自回归性质完全一致，使模型得以保留预训练 VLM 的文本生成能力：

$$\mathbf{O}_{\text{AR}}=\operatorname{Attn}_{\text{causal}}\!\bigl(\mathbf{Q}_{\text{AR}},\;\mathbf{K}_{\text{AR}},\;\mathbf{V}_{\text{AR}}\bigr).$$

#### 扩散子序列注意力。

DM 子序列中的 token 使用*全双向注意力（full bidirectional attention）*，并以 AR token 与 DM token 的并集作为键与值。这使得每个扩散 token 都能自由地关注来自自回归子序列的文本提示，以及序列中所有其他的条件 token 与扩散 token，从而维持时间与空间上的一致性：

$$\mathbf{O}_{\text{DM}}=\operatorname{Attn}_{\text{full}}\!\bigl(\mathbf{Q}_{\text{DM}},\;[\mathbf{K}_{\text{AR}};\,\mathbf{K}_{\text{DM}}],\;[\mathbf{V}_{\text{AR}};\,\mathbf{V}_{\text{DM}}]\bigr),$$

其中 $[\cdot\,;\cdot]$ 表示沿序列维度的拼接。需要指出，AR token 从不依据 DM token 被更新，这保持了条件通路的因果完整性。

## 2.4 多模态位置嵌入

位置嵌入向注意力机制注入时间与空间结构，促使 token 更强烈地关注语义与几何上相关的 token，而这些 token 通常在空间或时间上邻近。由于 Cosmos 3 在一个统一的注意力框架内联合建模语言、视觉、音频与动作 token，因此设计一套能够在各模态之间一致泛化的位置嵌入方案本身就具有内在的挑战性。受 3D 多模态 RoPE（MRoPE）(Bai et al., 2025a)启发，我们设计了一种带绝对时间索引的 3D MRoPE，以把视频、音频与动作 token 对齐到同一条物理时间轴上。原始的 3D MRoPE 把每个注意力头的隐维度划分为时间、高与宽三个分量，其中时间分量只记录离散的 token 索引。这一设计对图像与视频理解任务是足够的，但对我们的设定而言并不充分——在我们的设定中，视频、音频与动作 token 可能以不同的帧率或采样率被同时生成。在这种情况下，来自不同模态的 token 必须对齐到一条绝对物理时间轴。我们先介绍与原始 3D MRoPE 设计一致的基础形式，然后说明我们的扩展与修改，特别是我们用于对齐绝对时间轴的绝对时间调制。

### 2.4.1 位置索引分配

#### 自回归 token。

为了与语言生成以及图像/视频理解模型保持向后兼容，AR 子序列中所有语言 token 与 ViT 编码媒体 token 的位置索引沿用原始 3D MRoPE 设计。对于语言 token，$t=h=w$ 被设为同一个单调递增的值，从而把 3D MRoPE 约化为标准的 1D RoPE 行为。对于来自 ViT 编码器的 token，同一帧的所有 token 共享 $t$，而 $h$ 与 $w$ 索引依每个 token 的空间位置独立变化。自回归子序列中位置索引的分配与 Qwen3-VL(Bai et al., 2025a)中的 3D MRoPE 设计完全相同。

![Figure 6](figures/tikz_mrope_coordinate_assignment.svg)

> Figure 6: **3D MRoPE 下坐标分配的示意图。左：一条打包后的 token 序列，包含语言、视频（两帧，每帧 $2\times 2$ 空间网格）、音频与动作 token。每个 token 获得一个 $(t,h,w)$ 三元组。语言 token 使用 $t=h=w$；视频 token 在三个轴上都变化；动作与音频 token 只使用时间坐标（$h=w=0$）。一个模态偏移 $k$ 把文本与视觉的时间区间分隔开。右：FPS 调制把帧索引映射为缩放后的时间位置，使得在 16、24 与 30 FPS 下相等的真实世界时长占据相等的位置区间，其中 24 FPS 是我们的基准帧率。**

#### 扩散 token。

如图 6 所示，视频 token 在三个轴上都有变化：$t$ 随时间隐帧索引推进，而 $h$ 与 $w$ 在每帧内独立地按空间网格 $(0\ldots H{-}1,\;0\ldots W{-}1)$ 铺展。图像 token 被视为单帧视频，仅在 $(h,w)$ 上变化。空间索引与时间索引都在每个视觉片段起始处重置为零，因此模型把 $t$、$h$、$w$ 视为视频内的绝对坐标，而不是全局序列中的位置。举例而言，在视频转换任务中，用户提供一个文本提示以及一些受控的视频帧（如深度图），此时干净的控制视频 token 与带噪的生成视频 token 都从自回归子序列中最后一个 token 的时间偏移处开始。所有**音频 token** 与**动作 token** 只携带时间坐标，其空间索引被置为零（$h=w=0$）。对于音频 token，时间索引随每个音频跳步推进；对于动作 token，时间索引随每个采样步推进。

#### 自回归与扩散 token 的间隔。

在实践中我们发现，直接让扩散 token 从最后一个自回归 token 的时间偏移处接续开始，会导致初始视频帧出现过饱和与棋盘格伪影。这一现象在 Cosmos 3 规模更大的变体上尤为显著，例如 Super 模型。我们推测其发生的原因是：最后一个语言 token 与来自第一帧的视觉 token 占据了相邻的时间位置，导致时间嵌入几乎完全相同。为解决这一问题，受 Cao et al. (2025) 启发，我们在自回归子序列与扩散子序列之间插入一个固定的时间间隔，并把其后所有视觉、音频与动作 token 的时间索引统一平移。这在位置空间中形成了一个缓冲，提供一个更清晰的文本到视觉的过渡信号，同时无需架构上的改动或额外的可学习嵌入。在我们所有的模型中，该间隔都设为 $15000$。

### 2.4.2 绝对时间调制

沿时间维度的单个单位步长，在不同模态或不同数据源之间可能对应不同的物理时间间隔。例如，分别以 60 FPS 与 24 FPS 编码视频时，24-FPS 视频 token 的一次时间索引递增所对应的物理时间间隔，是 60-FPS 视频 token 所对应间隔的 2.5 倍。类似的不一致也出现在动作与音频 token 上，因为不同数据源可能使用不同的采样率。FPS 调制的设计目的，是通过调节每个时间增量的有效尺度，把具有不同时间分辨率的 token 对齐到一条共享的物理时间轴上。

我们首先定义每秒时间步数（temporal steps per second, TPS）来刻画物理时间分辨率。对于视频 token，TPS 由视频帧率除以时间压缩因子给出；由于视频 VAE 编码器的关系，该因子在我们的情形中为 4。对于音频 token，TPS 计算为 $\mathrm{TPS}_{\mathrm{audio}}=\frac{48000}{1920}\approx 25$（48 kHz、跳步 1920）。对于动作 token，TPS 恰好是动作数据的采样频率。

我们随后把沿时间维度的一个单位长度与一个基准 TPS 相关联，记作 $\mathrm{TPS}_{\mathrm{base}}$。对于给定的扩散子序列中的 token，我们计算它们各自对应的 TPS。当时间索引需要增加一个单位步长时，经过调制的实际时间增量 $\delta t$ 按下式计算

$$\delta t=\frac{\mathrm{TPS}_{\mathrm{base}}}{\mathrm{TPS}}.$$

由于视频在我们的训练数据中占多数，且 24 FPS 是我们设定中最常见的帧率，因此我们设 $\mathrm{TPS}_{\mathrm{base}}=\frac{24}{4}=6$，其中 $4$ 是我们视频 tokenizer 的时间压缩比。

## 2.5 模型变体

Cosmos 3 在三个模型规模上进行训练：**Edge**、**Nano** 与 **Super**，覆盖从端侧部署到大规模数据中心推理的宽广计算预算区间。**Edge** 是一个 4B 参数模型，构建在一个稠密的 2B 参数 Transformer 之上；**Nano** 是一个 16B 参数模型，构建在一个稠密的 8B 参数 Transformer 之上；**Super** 是一个 64B 参数模型，构建在一个稠密的 32B 参数 Transformer 之上。所有变体都从预训练的视觉-语言模型（VLM）初始化，并采用上文所述的混合 Transformer（MoT）架构。Tab. 2 汇总了每个变体的关键架构超参数。Cosmos3-Nano 与 Cosmos3-Super 模型在本论文中发布，Cosmos3-Edge 模型将在后续版本中加入。

**Cosmos3-Edge** 采用一个 $28$ 层的 2B 稠密 Transformer 设计：隐维度 $2048$、$16$ 个注意力头、$8$ 个键值头、头维度 $128$，以及 FFN 维度 $9216$。我们使用 Megatron 代码库从零训练该 LLM。其 LLM 的设计大体遵循 Qwen3-1.7B 架构，有两点显著差异：它去掉了 QK 归一化，并使用 ReLU² 作为 FFN 激活函数，后者与 Tab. 2 中所报告的 Edge FFN 维度相配套。

**Cosmos3-Nano** 适配 Qwen3-VL 8B(Bai et al., 2025b)架构，LLM 含 $36$ 层、隐维度 $4096$、$32$ 个注意力头、8 个键值头、头维度 $128$，以及 FFN 维度 $12{,}288$。

**Cosmos3-Super** 适配 Qwen3-VL 32B(Bai et al., 2025b)架构，LLM 含 $64$ 层、隐维度 $5120$、$64$ 个注意力头、$8$ 个键值头、头维度 $128$，以及 FFN 维度 $25{,}600$。
