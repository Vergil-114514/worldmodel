### 6.2.4 转换生成评测（Transfer Generation Evaluation）

#### 双权重无分类器引导（two-weight CFG）。

视频转换（video transfer）同时以一个结构化文本提示和一个控制视频为条件，而字幕保真度与结构遵循之间的最优平衡在不同模态上各不相同。为了独立控制这两个因素，我们使用一种带独立权重的双权重无分类器引导（two-weight classifier-free guidance）方案：一个权重用于控制视频，一个权重用于文本提示。

在每个去噪步骤，我们对去噪器求值三次——同时带两个条件、只带提示（丢弃控制视频）、以及保留控制视频但把提示替换为一个固定的负字幕（negative caption）。随后我们组合这些预测，使得控制权重从"仅提示"预测向"全条件"预测外推（强化结构控制），而文本权重则朝远离负提示预测的方向外推（强化字幕保真度）。把这两个权重作为独立旋钮暴露出来，让我们可以把每个模态调到各自的质量–保真度最佳点；我们发现这种因子化的引导比标准的单引导公式更有效。

#### 通用视频转换（General video transfer）。

我们在 PAIBench-C（NVIDIA, 2025e）上评测视频转换，这是一个控制条件的视频到视频基准，覆盖四个空间控制模态：blur（模糊）、edge（边缘）、segmentation（分割）与 depth（深度）。该基准包含 $600$ 个片段，跨越三个 Physical AI 领域：来自 AgiBot World（Bu et al., 2025）的 $200$ 个机械臂操作片段、来自 OpenDV（Yang et al., 2024）的 $200$ 个驾驶片段，以及来自 Ego-Exo-4D（Grauman et al., 2024）的 $200$ 个第一人称日常生活的片段。

对每个样例，模型接收一个文本提示与一个控制视频，必须生成一段遵循控制、同时保留提示所描述场景语义的写实视频。我们报告单控制设置（每个样例恰好一个模态），以便每个模态的贡献都能被孤立地度量。质量评估的方式是从生成视频与参考视频中重新提取相关控制信号，并在对应空间中比较它们（双边滤波后的 blur SSIM、Canny edge F1、在估计深度上的尺度无关 RMSE、在开放词表分割掩码上的 mIoU），再加上 DOVER（Wu et al., 2023a）作为一个与内容无关的感知真实度度量。

我们把 Cosmos 3 与 Cosmos-Transfer2.5 基线进行比较，后者通过每个模态一条专用 ControlNet（Zhang et al., 2023）分支来处理不同模态。需要注意的是，Cosmos 3 取而代之是一个统一模型，它在输入序列中同时消费控制视频与文本提示，无需按模态的 ControlNet 适配器即可原生支持任意模态组合。

Tab. 16 显示，尽管四条专用 ControlNet 分支被折叠进单一统一骨干，Cosmos 3 仍通过其两个变体之一在所有模态上追平或超过 Cosmos-Transfer2.5：Cosmos3-Nano 在感知质量（DOVER）与分割上领先，而 Cosmos3-Super 拿下几何上要求更高的 edge 与 depth 任务。三个模型在 blur SSIM 上基本持平，而该指标已接近其上界饱和。这些结果表明，按模态的 ControlNet 适配器并非强控制保真度的先决条件——单一统一骨干原生支持全部四种空间控制，并在每一项指标上、以两个规模之一击败专用适配器基线。

#### 自动驾驶（Autonomous driving）。

PAIBench-C 由一个 AV 专用基准补充：$486$ 个单视角驾驶片段（NVIDIA, 2025b），用于 world-scenario-map 条件的视频转换，称为 AVBench-C。控制输入是驾驶场景的相机视角渲染，它把静态地图结构（车道线、道路边界、交通信号灯与交通标志）与所有场景物体（车辆、行人及其他代理，含静止与运动）结合在一起。给定这一渲染场景以及一个文本提示，模型必须产生与两个输入都一致的写实驾驶视频。我们用自动评测与人工评测两种方式评估结果：

- • *AVBench-C 自动评测。* 我们用三个基于真值的自动检查器评测每次生成。*egomotion*（自运动）检查器使用视觉里程计计算每行驶一米的轨迹漂移。*object-correspondence*（物体对应）检查器把场景实体与控制输入匹配，将动态参与者与渲染轨迹比对、将静态结构与投影地图比对。*environment*（环境）检查器使用一个 VLM 评审对提示级的驾驶条件打分，包括天气、时段、区域与路面状态。

- • *AVBench-C 人工评测。* 受训标注员沿两个轴以 1–3 分对每个生成视频评级。*video quality*（视频质量）轴衡量整体真实度：3 表示纹理写实且代理行为时间上一致，2 表示轻微形变或短暂的时间卡顿，1 表示明显不真实的动力学或低质量纹理。*lane line*（车道线）轴衡量对 world-scenario map 的保真度：标注员把生成结果与一张预期道路布局的参考叠加图一起观看，如果车道、交叉口与实体大多在正确位置则给 3，如果少数车道缺失但多数实体放置正确则给 2，如果多数车道或交叉口缺失或实体错放则给 1。

### 6.2.5 动作生成评测（Action Generation Evaluation）

我们评测动作中期训练是否赋予 Cosmos 3 一个可跨领域、跨推理模式复用的世界-动作先验。核心问题是：统一的动作中期训练是否能加速对领域特定动作接口的适配，以及一段短的后训练阶段能否把共享基座模型变成与最先进领域基线相当、或更强的专用模型。Table 18 报告在相机运动、自动驾驶、机器人与第一人称运动领域上的结果，覆盖前向动力学与逆向动力学设置。Table 19 报告机器人策略设置上的结果，评测 Cosmos 3 完成语言指定任务的能力。

#### 设置（Setup）。

对每个下游领域，我们比较两种初始化协议。第一种是预训练初始化（*PT-init*），从 Cosmos 3 预训练检查点开始，该检查点没有在动作领域数据上训练过。第二种是中期训练初始化（*MT-init*），从我们的中期训练检查点开始，该检查点已见过跨越多个领域与预测模式的动作数据，包括前向动力学（FD）、逆向动力学（ID）与策略（policy）。对每次比较，我们使用相同的训练配方，并保持模型大小、数据与算力预算固定。我们同时报告 Cosmos3-Nano 与 Cosmos3-Super 的结果。

#### 指标（Metrics）。

我们为每个动作接口报告相应指标。对于自动驾驶车辆的逆向动力学，相对旋转误差（RRE）与相对平移误差（RTE）衡量逐帧位姿精度，而绝对轨迹误差（ATE）衡量全局轨迹一致性。我们也用这些指标衡量相机运动前向动力学中的相机跟随精度，比较真值相机位姿与从生成视频中估计出的相机轨迹。对于机器人与第一人称前向动力学，PSNR 衡量动作条件下未来观测的重建质量。尽管一段合理的生成 rollout 不必与唯一记录的真值未来在像素上完全一致，但我们发现 PSNR 在相对较短的时间跨度内是一个有用的代理指标，可反映时间对齐、运动一致性与重建保真度。对于机器人策略，成功率（success rate）衡量被成功完成的评测任务百分比。

#### 第一人称运动（Egocentric motion, FD）。

我们在前向动力学设置下评测来自 Human World Bench（HWB，见 Sec. 6.2.2）的视频。我们使用 HWB 的动作标注，它同时包含相机自运动与手部运动跟踪，并报告生成视频的 PSNR。我们把 *PT-init* 与 *MT-init* 两种检查点都适配到第一人称领域，并与 LOME（Gao et al., 2026a）比较——后者是近期一个专门面向第一人称手部操作数据的动作条件视频生成方法。尽管 LOME 是该设置下最接近的可用基线之一，但它在 HWB 上表现很差，PSNR 值为 9.36dB，这可能源于其训练数据与 HWB 基准之间的分布偏移。相比之下，Cosmos 3 在两个模型规模与两种初始化协议上都取得明显更高的 PSNR。使用 *PT-init* 时，Cosmos3-Nano 达到 15.22dB 的 PSNR 值，Cosmos3-Super 达到 15.34dB 的 PSNR 值。从 *MT-init* 开始可进一步提升到 Cosmos3-Nano 16.12dB、Cosmos3-Super 16.19dB 的 PSNR 值。这些结果表明 *MT-init* 提供了一致的增益，说明统一的动作中期训练为第一人称前向动力学提供了一个明显更强的起点。总体而言，这些结果支持了统一动作中期训练的核心假设：跨机器人本体、相机运动、自动驾驶车辆运动与第一人称运动的协同训练会诱发一个可迁移的动作领域先验，从而在第一人称领域实现更快的收敛与更强的下游适配。

#### 机器人（Robotics, FD）。

机器人前向动力学解锁了诸如用视频模型做策略评估等应用。我们在 DROID 数据集（Khazatsky et al., 2024）上做实验，这是一个大规模真实机器人操作数据集，场景与物体多样。给定一帧初始图像与大小为 16 的机器人末端执行器动作块（action chunk），模型预测随后的 16 帧。我们在 DROID 数据集上对 *PT-init* 与 *MT-init* 两种检查点都做后训练。我们以 Ctrl-World（Guo et al., 2026）作为主要基线进行比较。定性结果见 Fig. 24，定量结果见 Tab. 18。如 Tab. 18 所示，从预训练检查点开始的后训练在 Nano 规模上已能追平基线，达到 23.24dB 的 PSNR 值，而 Ctrl-World 为 22.99dB。从中期训练检查点开始的后训练带来显著更强的结果，Cosmos3-Nano 达到 25.52dB、Cosmos3-Super 达到 26.04dB 的 PSNR 值。这些结果表明 Cosmos 3 是前向动力学预测的一个强而灵活的骨干。

#### 动作数据协同（Action data synergy）。

选择哪些动作领域一起训练，是一个实际的混合设计问题：新增一个领域可以提供有用的视觉-动作先验，但它也可能稀释目标领域的监督。受近期关于语言领域迁移工作的启发（Longpre et al., 2026）——该工作度量在一种语言上训练如何惠及或干扰另一种语言——我们为动作中期训练构建了类似的迁移图谱，覆盖自运动领域（Camera Motion、Autonomous Vehicle）、机器人操作领域（Google Robot、WidowX-250、Franka Panda Single、Franka Panda Dual、AgiBot）与人类第一人称运动（Egocentric）。定量协同矩阵汇总于 Figure 28 与 Figure 29。FD 报告 PSNR，ID 报告 MSE。对于策略模式，我们报告 4 次 rollout 上的最小 PSNR 与 MSE，因为 rollout 分布是多峰的。在每个协同矩阵中，非对角单元格使用行领域与列领域的 50/50 混合训练 4,000 次迭代，而对角单元格是相应的单领域基线，训练 2,000 次迭代。这一设置使单领域与配对运行之间在每个领域的训练预算相匹配。每一行固定评测领域，列则在单领域或配对训练设置之间变化。正 delta 表示跨领域迁移，负 delta 表示干扰。

- • *相机运动从广泛的动作协同训练中受益。* Figure 28 显示，相机运动作为表现较弱的领域之一，从若干协同训练伙伴（而非仅从另一个自运动来源）中获益。AV 数据把相机 FD PSNR 从 11.96 提升到 12.82（+0.86），而机器人领域也提供正的 FD 增益，包括 Google Robot（+0.79）、Franka Panda Single（+0.73）与 Franka Panda Dual（+0.48）。该行的 ID MSE 对每一个所示协同训练伙伴也都改善。这表明相机运动的学习受益于一般的动作条件视觉先验，例如物体持存性、场景几何与运动对应线索，即使新增领域具有不同的本体。

- • *机器人操作领域共享早期训练先验。* Figure 28 中的机器人领域面板显示操作数据集之间存在广泛的早期迁移，尤其是对那些单领域基线表现较差、或数据更异质的领域。WidowX-250 从 Google Robot 强烈受益，获得 +1.39 的 FD PSNR 与 +2.29 的策略 PSNR，并在 ID 与策略 MSE 上有相应改善。Google Robot 也从若干机器人协同训练伙伴受益，FD PSNR 提升最高达 +0.89，策略 PSNR 提升最高达 +1.44。相比之下，本次协同研究中 Franka Panda 单臂与双臂条目对应的是小规模的 RoboMIND Franka 子集（Wu et al., 2025a），分别只有 23 与 4 小时的数据。与 Figure 9 中汇总的远为庞大的动作数据来源相比，这些小目标领域在单领域训练下很快饱和，因此加入更大的协同训练领域在它们自身的评测上带来的收益较小或有正有负。然而，当它们作为被协同训练的来源使用时，仍然对其他领域提供有用的迁移。

#### 结论（Conclusion）。

我们表明 Cosmos 3 是一个跨多样领域、本体与推理模式的强动作基础模型。单一基础模型可以被适配到相机控制视频生成、自动驾驶车辆逆向动力学、第一人称手部前向动力学、机器人前向动力学以及机器人策略学习，同时保持与专用领域基线相当或更强。*PT-init* 与 *MT-init* 的进一步比较表明，统一的动作中期训练所做的不只是改善孤立领域：它产生了一个可复用的动作领域先验，加速了跨下游设置的收敛，包括对新本体与新环境的适配。这一点格外值得注意，因为所评测的领域在本体与监督形式上差异极大，从相机与车辆运动到有关节的人类手部与机器人末端执行器。协同研究提供了动作领域共享可迁移结构的证据：跨自运动、机器人操作与第一人称运动的协同训练可以改善早期适配，尤其是对那些单领域基线较弱的领域。Appendix E.4 与 E.5 中额外的动作特定消融支持同一结论：FD、ID 与策略目标在联合训练下共享有用的结构，并且与策略动作一同预测的视频，与由这些相同动作驱动的仿真器 rollout 保持一致。总体而言，这些发现支持 Cosmos 3 作为一个通用世界-动作基础模型，可以被高效地专门化到广泛的动作生成与控制任务上。

## 6.3 生成器使用指南（Generator User Guide）

虽然基准结果为生成质量提供了定量评估，但要有效使用一个全模态世界模型，还需要理解其推理接口、提示方法与采样配置。由于 Cosmos 3 支持多样的模态与生成模式——包括图像、视频、音频-视觉、转换（transfer）、前向动力学、逆向动力学与策略生成——输出的质量不仅取决于模型权重，也取决于生成请求如何被指定与条件化。本节提供使用 Cosmos 3 Generator 的实践指南，包括推荐的提示策略、结构化字幕格式、采样超参数，以及 Cosmos 3 Reasoner 作为提示词上采样器（prompt upsampler）的作用。这些指南反映了我们在全部评测中所使用的配置，可作为在广泛的 Physical AI 应用中获得高质量、物理上合理生成的参考。

### 6.3.1 生成指南（Generation Guide）

Cosmos 3 Generator 支持在宽广推理包络内的灵活视觉（及音频-视觉）生成：帧率 10–30 FPS、5 到 400 帧、分辨率覆盖 256p、480p 与 720p，以及常见宽高比（1:1、3:4、4:3、9:16、16:9）。这使得单一模型可以服务从短的预览片段到更长、更高分辨率的横屏或竖屏视频等多种用例，而无需改变采样接口。Cosmos 3 Generator 针对前向动力学、逆向动力学与策略模式训练，以支持不同的动作相关应用。对于动作生成，基础的 Cosmos3-Nano 与 Cosmos3-Super 模型支持原生控制频率在 10–30 FPS 范围内的动作预测，在逆向动力学与策略模式下预测跨度覆盖 16–400 帧。后训练模型则专门化到单一模式与单一频率——例如，Cosmos3-Nano-Policy-DROID 以 15 FPS 运行，预测范围为 32 步（32-step prediction horizon）。下面我们将详述使用 Cosmos 3 Generator 成功生成的关键组件。这些细节也汇总于 Tab. 21。

#### 媒体规格与提示指南（Media specifications and prompting guide）。

Cosmos 3 Generator 在结构化 JSON 字幕上训练，这些字幕对场景构成提供细粒度控制，涵盖主体、背景、光照、美学、摄影，以及视频特有的时间字段（如动作、状态变化、相机运动与分段级描述；完整 schema 见 Appendix A）。在推理时，一个提示词上采样器——由 Claude Opus 4.6 或 Cosmos 3 Reasoner 提供服务——把用户请求转换为同样的这一结构化格式，确保生成提示匹配训练期间所见的分布（模板指令见 Appendix B.1）。上采样器被指示先描述场景布局与世界状态，再指定事件的时间推进，最后加入任何音频描述。具体的上采样指令在各生成模式之间略有差异——例如，动作生成与转换生成会施加针对其条件输入定制的额外任务约束（转换生成的提示前缀见 Appendix B.4，动作提示指南见 Appendix B.5）。JSON 规范还额外包含显式的媒体控制（duration、FPS、空间高度与宽度、宽高比），使提示解释与采样配置保持可检查、可复现。

#### 负提示（Negative prompt）。

我们通过自动化基准迭代，为每个模型与生成模式单独调优负提示。对每个配置，我们在候选模板上做消融，候选范围包括自然语言描述、关键词列表、指令式命令、面向物理一致性与身份保持的组合式扩展，以及空字符串。表现最佳的变体依据自动化基准分数选出。对于基础的 Cosmos3-Nano 与 Cosmos3-Super 生成器，显式负提示见 Appendix B.6。对于后训练变体，我们发现空字符串负提示对 Cosmos3-Super-Text2Image 效果最好，而对 Cosmos3-Super-Image2Video，使用从用户提示自动派生的负提示取得最佳结果（Appendix B.3）。对于动作生成模式，我们发现空字符串负提示效果最好。

#### 生成采样超参数（Generation sampling hyperparameters）。

我们对不同模态采用以下采样参数：

1. 1. *音频-视觉生成。* 对于音频-视觉生成，我们在图像与视频生成的自动化基准（Sec. 6.2.1 与 Sec. 6.2.2）上调优采样超参数。对于基础的 Cosmos3-Nano 与 Cosmos3-Super 生成器，我们使用 50 个去噪步、guidance scale 为 6、time shift 为 10，以及全范围无分类器引导（full-range classifier-free guidance）。对于后训练的 Cosmos3-Super-Text2Image 模型，我们使用 guidance scale 4 与 time shift 3。对于后训练的 Cosmos3-Super-Image2Video 模型，我们使用 shift 5。

1. 2. *动作生成。* 动作生成支持三种模式。对于前向与逆向动力学，我们使用 50 个去噪步、guidance scale 为 1、time shift 为 5，以及全范围无分类器引导。对于策略模式，我们切换为 4 个去噪步、guidance scale 为 3。

1. 3. *转换生成。* 我们在自动化 PAIBench-C 基准（Sec. 6.2.4）上调优视频转换生成的采样超参数。我们使用 50 个去噪步、文本 guidance scale 为 3、控制 guidance scale 为 1.5、time shift 为 10，以及全范围无分类器引导。

### 6.3.2 以 Cosmos 3 Reasoner 作为提示词上采样器（Cosmos 3 Reasoner as Prompt Upsampler）

提示词上采样是 Cosmos 3 中在生成之前的推理步骤，它把紧凑的用户意图转换为结构化的时空场景规范。它不是仅仅重写提示，而是把稀疏的用户输入扩展成一种物理上接地的控制语言，捕捉场景布局、时间演化，以及（在适用时）音频线索。用户通常只提供一段简短的自然语言请求，而高质量的图像与视频生成依赖于许多很少被显式指定的细节，例如主体属性、空间布局、相机行为、光照、时间顺序、音频线索，以及诸如分辨率、宽高比、duration 与 frame rate 的生成控制。上采样器通过在用户界面与生成器之间充当一个指令跟随的 LLM 模块来填补这一空缺。它接收简短请求、输出的结构模板，加上可选的条件输入信号（例如 image-to-video 的起始图像），产出一份稠密的、带类型的 JSON 场景规范，供下游图像或视频模型据此渲染。

先前工作分为两条脉络。第一条脉络把简短的用户查询映射为更丰富的文本提示以用于图像生成。DALL-E 3 使用描述性重打字幕与字幕上采样，以更好地匹配生成器的字幕分布（Betker et al., 2023）；Prompt Expansion 显式地学习把一个查询扩展为多个优化的文本到图像提示（Datta et al., 2024）；而 Promptist、BeautifulPrompt 与 RePrompt 这类提示适配系统训练语言模型把用户输入重写为模型偏好的提示，同时优化图像级目标（Hao et al., 2023; Cao et al., 2023; Wu et al., 2025b）。第二条脉络使用 LLM 作为下游视觉生成器的规划器，产出物体布局、接地的场景描述、帧级提示或多场景视频计划（Lian et al., 2024; Feng et al., 2023; Hong et al., 2023; Lin et al., 2023）。Cosmos 3 采纳了"在生成前插入一个推理模块"这一相同的基本思路，但进一步改变了接口。上采样器输出的是一个带类型的多模态场景程序，而不只是一个重写后的提示或生成器专用的布局计划；并且该程序横跨图像、视频与音频条件的生成。从某种意义上说，上采样器的做法是：先想象场景，考虑其时间/空间方面，在一个抽象语言描述状态中添加进一步的多模态内容（例如音频描述符），再把它们翻译为匹配所提供模板的结构化输出。

我们把上采样视为一种在*结构化数据*上、带*物理先验*的复杂*多模态*指令跟随。输入可以是纯文本、图像加文本，或视频加文本。输出是一个 schema 约束的 JSON 控制程序，它捕捉语义内容、视觉属性、任务特定字幕、视频任务的时间计划、视频任务的音频描述字段，以及渲染器所需的生成参数。结构化输出不只是一个格式上的选择：它暴露出生成器必须以其为条件的隐变量，包括实体、空间关系、动作、时序、相机行为、音频后果与生成控制。这把提示词上采样与"结构化 LLM 推理与验证"这一工作体系联系起来——在那里，自然语言指令被转换为在结构化字段上的显式、可检查的程序（Chegini et al., 2025）。同时，填写一个稠密的场景 schema 需要在不确定性下推理：上采样器必须从不完整的用户输入中推断出可能的物体状态、时间转换、因果交互与声学结果（Pournemat et al., 2025），从而在不违背所施加之现实的物理约束的前提下，沿创造力轴扩展。在 Cosmos 3 中，这些概率与物理先验通过 schema 本身表达。模型先想象一个连贯的世界状态，然后把它映射为一个时间 rollout，最后导出与可见事件保持同步的音频线索。这种分离是有用的，因为它把提示理解暴露为一个可独立检查的组件，而不是与渲染模型纠缠在一起。

#### 提示契约（Prompt contract）。

在推理时，上采样器接收用户描述以及所选的生成控制。对于 image-to-video 生成，它还接收条件图像，该图像被视为第一帧的确凿视觉证据。请求被格式化为四个带标签的区块：1) instructions 区块：介绍所有区块，定义任务级行为，例如产出单个围栏式（fenced）JSON 对象、避免额外评论，以及把模板视为强制。2) image 或 video _description 区块：承载原始语义请求；对于 I2V 这类受条件约束的请求，附带的条件内容与该文本一同提供，且约束规定了视觉事实应如何锚定于它。3) task_constraints 区块：承载大部分操作细节。它指定字段顺序、时间格式、duration 上下界、需照抄的控制项（如分辨率、宽高比、duration 与 frame rate）、对用户所提供实体与动作的保持要求，以及任务特定的接地规则（例如在 $t=0$ 处匹配 I2V 的第一帧）。4) output_json_template 区块：定义 schema 表面：哪些键必须填充、期望哪些嵌套字段，以及场景、时间、音频、主体、相机、光照、风格与控制信息应放置在何处。换言之，约束描述上采样器应当如何推理与照抄取值，而 JSON 模板定义最终答案必须采取的形状。系统提示是一个极简的 "You are a helpful assistant"（英文原文，即传给上采样器的 system prompt 字面值）。完整模板见 appendix B.1。使用该模板时，某些占位参数（如 description、FPS、duration、宽高比、resolution 等）必须在传给 Upsampler 之前相应填好。
