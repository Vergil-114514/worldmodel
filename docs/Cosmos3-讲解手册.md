## 1. 引言（全译 72–112）

**它在争什么。** 一句话：物理 AI 需要两种能力——**理解**（从残缺观测推出隐状态、语义、动力学）和**生成**（预测世界如何演化、我该怎么动）。以往这两件事分给不同模型家族：VLM 管理解，视频生成/前向动力学模型管仿真，VLA/WAM 管动作。作者说这种割裂"从根本上受限"，理由不是工程麻烦而是**认识论上的互相依赖**：理解必须预判行为后果，生成必须依赖一个紧凑结构化的世界表示。

**为什么这值得你停下来想。** 家用机器人"饭后擦桌子"的例子是全篇最好的一段（全译 84 附近）：现有做法要串 VLM 定位餐具 → VLA 出动作 → 世界模型评估后果，三个模型三套数据三套 loss，信息在接口处反复丢失。Cosmos 3 的做法是：**同一批 token 序列、同一套 Transformer、两种目标函数**。这是全篇的设计母题，后面 §2 全是它的展开。

**它的证据结构。** 全译 96 那张 Table 1 是"结果总览"，四个理解列 + 六个生成列，覆盖 VLM / 文生图 / 文生视频 / 图生视频 / 音频 / 前向动力学 / 策略。带 `*` 的是后训练变体，`†` 是闭源，灰色格=不具备该能力（HTML 版灰色丢了，只剩空格，见「校注」）。

**读这一节时的怀疑点。** Table 1 显示通用推理列 Gemini 3.1 Pro **77.5** > Cosmos3-Super **73.7**——它没赢在通用 VLM 能力上。这一点原文没回避，别被"全面 SOTA"的摘要带跑：Cosmos 3 的卖点是**统一**与**物理/具身**列，不是当最强通用 VLM。

## 2. 模型架构（全译 113–272）——本手册最长的一节

### 2.1 编码器：四个模态，四种处理态度（全译 117–156）

统一规则：**每种模态一个自己的编码器 → 投到同一个隐空间 → 加一个可学的模态嵌入**（让共享参数认得出"这是音频还是动作"）。差别在**冻结与否**：

| 模态 | 编码器 | 关键参数 | 训练时 |
|---|---|---|---|
| 语言 | tokenizer | 词表 131072 | 联训 |
| 视觉·理解 | 预训练 ViT | patch 16×16，2×2 merge，DeepStack，插文本化时间戳 | **联训** |
| 视觉·生成 | **Wan2.2-TI2V-5B 视频 VAE** | 时间 4×、空间 32×32（16×16 + 2×2），latent 通道 48 | **冻结** |
| 音频 | audio VAE | 48 kHz 立体声，hop 1920 → 25 token/s | **冻结** |
| 动作 | 域感知线性投影 | 每本体域一套 in/out 矩阵 | 联训（从零） |

**为什么这么切。** VAE 定义"latent 世界长什么样"，一动，扩散目标的几何就漂了；ViT 是"眼睛"，必须跟着语言走才能对齐语义。这是所有统一多模态模型都会撞到的取舍，Cosmos 3 选了"借现成 VAE + 自训理解侧"。

**这里有个可复核的关键点**：借 Wan2.2 的 VAE 不是免费的——§5.2.6 整节都在讲它太慢（见 §5 讲解）。理解这一前一后两节，你就懂"少造轮子"的真实成本在哪。

**动作表示（全译 129–156）——最像硬件工程师写的一节。** 它不喂 PID/底层驱动量，而喂三类几何量：
- ego pose 9D = 3D 平移 + 6D 旋转（6D 是过参数化表示，因为旋转真实自由度是 3；解出来再用 SVD 投回 SO(3)）
- effector pose 9D（同上）
- grasp state：手 15D（指尖位置）/ 夹爪 1D（开合）

相对运动用 $\Delta T = T_{t-1}^{-1}T_t$（**状态差**，即"伪动作"）。于是异构本体被压成同一族向量：AV 9D、相机 9D、第一人称 57D、单臂 10D、双臂 20D、人形 29D。

**【对账】** 我在 Edge 的 `transformer/*.safetensors` 里查到 `action_proj_in.fc` 形状 **[32, 131072]**，131072 = 64 × 2048 = action_dim × hidden_size。也就是说式(1)(2) 的"每个域一套矩阵"不是修辞，是**32 张 64→2048 的投影表摊平存一层**。`action_dim=64` 是统一动作槽位宽度，各本体把自己的 n 维填进前 n 个槽。

### 2.2 一条序列：AR 段在前，DM 段在后（全译 157–190）

这是理解 Cosmos 3 的第二把钥匙。序列固定长成：

```
[ 语言 token, ViT 视觉 token, ⟨EOS⟩, ⟨BOG⟩ ] ‖ [ VAE 视觉(干净条件→带噪目标), 音频, 动作 ]
   ← AR 子序列（推理器塔）                      ← DM 子序列（生成器塔）
```

三条排布规则（全译 161）：AR 永远在前；DM 内**干净条件 token 在带噪 token 之前**；同一段内按 视觉→音频→动作 排。

然后看式 (3)–(6)（全译 171 之后）就明白"统一"有多便宜：

| 任务 | 序列 | 换的只是 |
|---|---|---|
| 文生图 | $[S_{AR}, \tilde v_1]$ | 无干净视觉条件 |
| 文生视频(+音) | $[S_{AR}, \tilde v_{1:N}, \tilde s]$ | 目标帧变多 |
| 图/视频生视频 | $[S_{AR}, v_{1:P}, \tilde v_{P+1:N}]$ | 前面 P 帧干净：P=1 即图生视频 |
| 视频转换(Transfer) | $[S_{AR}, v^{ctrl}, \tilde v]$ | 干净条件是 depth/blur/edge/seg 的控制视频 |
| 动作三模式 | 同上，改**谁带噪** | 前向动力学=去噪视觉；逆向=去噪动作；策略=两者都去噪 |

注意符号：源里帧数用 $N$、条件帧数用 $P$（我早先笔记里写 $F$/$k$ 是错的，已在精读笔记的更正表里列出）。

**读法建议**：把 §2.2.2 当成"任务 = 掩码配置"来看。所有能力差异都不改架构，只改哪些 token 参与 loss、哪些是条件。这就是它能"吃掉 VLM+视频模型+WAM"的机制。

### 2.3 MoT 双塔（全译 191–220）

每个解码层两套完整参数（LN、注意力投影、MLP 各自独立），**两套都从同一个预训练 VLM 初始化**。注意力掩码非对称：

$$O_{AR} = \mathrm{Attn}_{causal}(Q_{AR}, K_{AR}, V_{AR}) \qquad O_{DM} = \mathrm{Attn}_{full}(Q_{DM}, [K_{AR};K_{DM}], [V_{AR};V_{DM}])$$

三条推论，值得背下来：
1. **生成以理解为条件**（DM 能看 AR），但**AR 永远看不到 DM** → 保住 VLM 的自回归性与条件通路因果性。
2. 双塔**不是 MoE**：没有 router、没有 top-k 专家，路由是**按 token 类型硬分派**。
3. "统一"省的是**流水线与数据协同 + AR 段只算一次**，不省显存——两塔参数是实打实的双份。

**【对账】** Edge checkpoint：AR 塔 1.4094B、DM 塔 1.4094B（严格相等）；DM 侧权重名是 `*_moe_gen`、`add_q_proj/add_k_proj/add_v_proj/to_add_out/norm_added_q/k` —— 这套命名是 **FLUX 双流块**的血统。另有一处正文没写：`k_norm_und_for_gen`（配置 `use_und_k_norm_for_gen: true`），**生成塔的 Key 归一化复用理解塔那一份**。

**训练目标的分家**（§4.2 会细讲）：语言走 next-token；其余模态走 **rectified flow matching**（预测速度场）。图 5 的图题里那句"trained in practice with a flow-matching objective predicting velocity"就是这条。

### 2.4 3D mRoPE 与两处关键改动（全译 221–254）

基础是 Qwen3-VL 的 3D MRoPE：每个头的隐维切成 (t,h,w) 三段（Edge 实测 `mrope_section [24,20,20]`）。分配规则：语言 $t=h=w$（退化成 1D RoPE）；ViT 视觉同帧共享 $t$；DM 视频三轴都变，但**每个视觉片段开头把 (t,h,w) 清零**（当作片段内绝对坐标）；音频/动作只走时间轴，$h=w=0$。

**改动一：AR↔DM 之间插 15000 的时间 gap（全译 225 附近）。** 若让扩散 token 直接续在 AR 末尾，最后一个文本 token 与第一帧视觉 token 的时间嵌入几乎相同 → **初始帧过饱和 + 棋盘格伪影**，模型越大越明显（点名 Super）。插一个固定缓冲即可，不引入任何可学参数。
> 这是那种"论文里一句话、复现时值一周"的细节。你在别的统一模型里看到首帧发糊/格纹，第一件该查的就是位置索引是否共点。

**改动二：绝对时间调制（全译 243）。** 定义 TPS（每秒时间步数）：视频 = FPS/4、音频 = 48000/1920 ≈ 25、动作 = 采样率。基准 $\mathrm{TPS}_{base} = 24/4 = 6$，索引增量取 $\delta t = \mathrm{TPS}_{base}/\mathrm{TPS}$。效果：16/24/30 FPS 下**相等真实时长占相等位置区间**（图 6）。
> 直觉：时间轴不再数 token，而是数秒。同步生成视频+音频+动作时，这是唯一能让三者对上的办法。

## 3. 数据（全译 273–493）——"为什么别人追不上"在这章

结构：两条路径、两套课程。推理器吃**成对的视觉-语言**数据；生成器吃**大规模图像/视频/音频/动作**、用重建式（flow matching）目标而非显式标注。

### 3.1 推理器：24.2M 样本与一道"三阈值"闸门（全译 279–383）

| 阶段 | 总量 | 构成 |
|---|---|---|
| 预训练 | **22,002,013** | 图文 18,814,952 / 视频-文本 1,016,299 / 纯文本 2,170,762 |
| 监督微调 | **2,171,673** | 图文 1,051,513 / 视频-文本 1,079,200 / 纯文本 40,960 |

（Table 3，全译 285 附近；这些整数我在 HTML 表体里逐格取过，不是估的。）

预训练构成：**OCR 9.44M（42.9%）、2D grounding 3.62M（16.5%）、VQA 2.48M（11.3%）、图像推理 1.66M（7.5%）**，其余是文本 QA / 图述 / 视频 QA / 指令数据。主干取自 Nemotron Nano 2 的 19.7M 子集 + 2.3M 增补。注意 SFT 阶段视频-文本占 **50%**——理解侧的"时空化"是在 SFT 才重仓。

清洗管线两问：**重复吗？对不对？**
1. 语义去重：对话级联合嵌入（图文/纯文本用 Qwen3-VL-Embedding-8B，视频用 PE-Core-G14-448）→ K-means 分簇 → 簇内余弦相似度 **>0.95 判重** → 总移除 **4.23%**。
2. AI 评审（Gemma-4-31B-it 当审计员）：忠实性/完整性/正确性各 1–5 分，**三阈值同时达标**才留（不是取平均！任一维崩就丢）。阈值 2 保留 **78%**、阈值 5 保留 **46%**；预训练用 2、**SFT 用 5**。

**这条最值得你抄**：取"最低有意义阈值"给预训练保多样性，用"高阈值"给 SFT 保精度；且它明确说"任一维失效即丢"——这是防幻觉标注的正确姿势。

### 3.1.2 SFT 的领域配料（全译 330–383）

自动驾驶 / 机器人 / 智慧基建三域。几个规模点：动作 CoT 人标 >10K + 自动标注 ~1.1M；Nexar 行车记录仪 24K 视频；手术 VQA **398K 对话 / 2.2M 图像**；仓库空间智能 93K RGB-D + 873K QA → 采 80K；密集行人 208K 图 / **5.6M** 人框；MimicGen 子任务切分（3,600 视频、60 留出零样本）；BEHAVIOR-1K 83K；物理合理性用 VideoPhy-2 3.4K/200 动作 + 自建 13.5K 元组/1K 生成视频。

### 3.2 生成器数据：数量级与配比（全译 384–493）

**预训练规模**：**767M 图像 + 347.7M 视频片段**，从 **7.8B 原始图像 / 3B 原始视频**清洗而来。分辨率分布：720p 占图 26.8%、视频 36.4%；480p 占 26.0%/30.8%；≥1080p 占 25.2%/12.2%；16:9 占图 52.0%、视频 **97.3%**（→ 你的竖屏素材是少数派）。

管线四步（全译 392 之后）：TransNetV2 分镜 → `ffmpeg cropdetect` 去黑边 → 嵌入（图 Qwen3-VL-Embedding-8B、视频 Cosmos-Embed1-448p）+ **cuML KMeans 20,000 簇**去近重复（在 147M 图 / 400M 片段子集上跑）→ 47 类层次打标 + 质量过滤（图：美学/真实感/拼贴/水印/NSFW；视频：DOVER 美学、DOVER 技术、VTSS 训练适用性 各 0–9 + 约 100 个伪影二值标签，分屏/旋转/静态判死，文字叠加/运动模糊/压缩噪声只标记不判死）。

**中期训练**是"能力注入"阶段，配比记得住：图像 **60% 真实 / 36% 合成 / 4% 文字渲染**；视频 **46.0% 预训练精选 / 43.9% 领域特定（机器人、AV、人类活动、第一人称）/ 10.1% 困难案例**。合成数据就是那五个 SDG 数据集（PhyxSim / RobotSim / DriveSim / SynHuman / Warehouse，HuggingFace 可下，**开源可直接拿来做消融**）。转换（transfer）条件数据：3M 视频，edge/blur 训练时在线算（Canny/高斯/双边，参数随机），depth/seg 离线算（Video Depth Anything / SAMv2），world-scenario 用 **MADS 1.1M × 7 路同步相机 @30FPS**，14 区域 / 25 国家-时长分区。

**标注（caption）是生成质量的上游**。他们对所有阶段用**结构化 JSON 标注**而非自由文本，理由是自由文本"精确但不全"；并自建标注质量基准，在**断言层**算精确率（对照原图/原视频核每条原子主张，罚幻觉）与召回率（人工原子断言真值 + LLM 比对）。微调了两个 Qwen3-VL-8B 分别当图像/视频标注器（细节在附录 A）。

**音频（全译 432–457）**：预训练 138.9M 片段带可用音轨（其中 62.5M 短于 30 秒）；中期训练池 **18.8M = 12.8M 非语音 + 6M 语音同步**。清洗逻辑一句话可复述：**语音只有在画面里有同步人脸时才留；非语音样本里画面外语音要剥掉；非器乐背景音乐会盖住目标音就剥**。工具链：SAM-Audio 分离、SyncNet 唇同（confidence ≥3.0）、FireRedASR2S 语音/音乐占比、Qwen3-VL 判是否乐器、Qwen3-ASR 转录 + GPT-OSS-120B 合并描述。
> 这就是"音视频同步"背后的脏活。想自己造同步数据，这套判据可以直接抄。

**动作（全译 458–493）**：**8.4M episode / 61.3K 小时**，四支柱占比 **第一人称 41.3Kh(67.4%) / AV 10.0Kh(16.3%) / 机器人 5.4Kh(8.7%) / 相机运动 4.6Kh(7.5%)**。机器人细分见 Table 4（AgiBot 239.4K episode / 4.37Kh；Franka 76.3K/442h；WidowX-250 50.4K/100.1h；UMI 38.3K/67h；UR 25.0K/35h；合计 516.7K/5.36Kh）。相机运动用 ViPE + DepthAnything3 反解位姿当伪动作（1.9M 片段），**保留空闲帧并在元数据记数**（让下游能自己配平，而不是丢掉信息）。

**这一节的读法**：不要背数字，背**配比**。67.4% 是第一人称——这解释了为什么它的人手/灵巧运动生成明显强于抓取机器人小数据；也解释了 §6.2.5 里 Egocentric↔AgiBot 的迁移协同（Figure 29）。

## 4. 训练（全译 494–659）——可直接抄的配方章

### 4.1 推理器（全译 498–519）

两阶段：**大规模多模态预训练 → Physical AI 专门化 SFT**。三处与常见做法不同：

1. **不做"先冻主干、只训 projector"的对齐阶段**，从第一步就全联训（作者明说试过后认为没必要）。
2. **√n 归一化的 per-token loss 加权**，平衡长短序列——他们说这显著改善下游分数与稳定性。
3. **SFT 里掺 1/5 的预训练数据**（预训练:SFT 采样预算 **1:4**）+ 800K 指令跟随数据，防"专精化把通用能力练没"。

超参（照抄自源文）：

| 项 | 预训练 | 监督微调 |
|---|---|---|
| 迭代/epoch | 全量混合 2 epoch | **8200** iter，global batch **512** |
| lr（LM+projector / ViT） | 5e-5 / 5e-6 | 1e-5 / 1e-6 |
| warmup / 衰减 | 10% 线性 → cosine 到 0.1× | 1000 步 → cosine 到 0.1× |
| Adam β / wd / clip | (0.9, **0.999**) / 0.05 / 1.0 | (0.9, **0.95**) / **0.1** / 1.0 |
| 序列上限 | 16k token（单样本 2048 图 / 8192 视频 token） | 同 |

> **最容易抄错的地方**：SFT 的 β₂ 从 0.999 降到 0.95、wd 从 0.05 升到 0.1。

### 4.2 生成器：目标函数与课程（全译 520–659）

**先读懂目标函数（全译 522 附近，源里是行内公式）：**
$$x_{\sigma}=\sigma\cdot\epsilon+(1-\sigma)\cdot x_{0},\qquad v^{*}=\epsilon-x_{0},\qquad \text{损失}=\|v_{\theta}(x_\sigma,\sigma,c)-v^*\|^2_{\text{masked}}$$
即 **rectified flow matching（整流流匹配）**：直线上插值造带噪 latent，网络学**恒定速度场**；条件 token 用 mask 踢出 loss。三个易被忽略的细节：
- **逐模态独立采样** $\sigma$（图/视频/音/动各自抽），因为四者时间尺度差一个数量级；
- 图像/音频/动作用 **logit-normal**，视频用 **mode sampling**（实测质量更好）；
- 噪声位移重参数化 $\sigma=s\cdot\bar t/(1+(s-1)\bar t)$，$\bar t=1-t$，$s\ge1$ 把分布推向高噪端。

**多分辨率与打包（全译 528–576）**：三档同训，256p 吃全量源、480p/720p 只吃原生够清的；帧预算 400/400/300；batch 配比 **image : 256p : 480p : 720p = 1 : 1 : 2 : 1**；shift **s = 1 / 3 / 5**；变长序列打包进**固定 74,000 token** 上下文（不 padding、不反复重编译）。训练模式占比 **T2I 20% / T2V 56% / I2V 16% / V2V 8%**，视频内部条件模式另有 T2V 70% / I2V 20% / V2V 10%（图 10）——两组数别混。
优化器 FusedAdamW lr 1e-4、β=(0.9,0.99)、wd 0.05、clip 1.0、loss scale 10，线性衰减到峰值 **0.30×**；文本 dropout **10%**（CFG 用）。训练量：**Nano 预训练 31.05T token @1024 GB200；中期训练 2.4T token**（表 8 表题写 2048/4096，与正文不一致，见「校注」）。

**中期训练（全译 577–621）**：shift 提高到 **3/5/10**；动作损失系数 **10×**；开始引入动作与 transfer 数据；LR 用 LambdaLinear（起始因子 0.4，周期 100,000）。

**三种后训练（这才是"能不能用"的答案）**：
1. **文生图 Super-Text2Image（全译 622）**：两阶段 SFT。阶段1 **20k** 步 @1e-4（2k warmup），配比 **45% 真实 / 40% 合成 / 15% 纯文字渲染**；阶段2 **2k** 步、**470k** 超高质图文对；固定 70k 上下文、**只训 >720p**。
2. **图生视频 Super-Image2Video（全译 636）**：**10k** 步 @1e-5，480p、**189 帧**、24 FPS，约 **50B** token，掺 20% T2I token。
3. **机器人策略 Nano-Policy-DROID（全译 648）**：从 Nano 中期权重续训，**动作编码器/解码 MLP/action token 全新初始化并给 5× 学习率倍率**；输入=本体感受 + **三视图**（360×640 主视 + 2×180×320 → 540×640 画布）；DROID **76k 轨迹 / 350 小时 / 86 任务 / 564 场景**；控制 **32 个动作 @15Hz**；推理只跑 **4 个扩散步**、shift 5、CFG 3，用 2 张 RTX Pro 6000 闭环。
> 第 3 点是全篇最"物理 AI"的证据：**把视频模型改造成策略，代价是重训一个动作头**，而不是重训整个模型。

## 5. 基础设施（全译 660–1021）——工程含金量最高、最容易被跳过

**5.1 数据侧（全译 676–735）**：**SILA**（可扩展数据处理与标注基础设施）以 Lance 列式数据集为唯一真源，**追加 typed 列**做增量富化；fragment 级协调与故障恢复、分阶段 Ray 执行、节点内模型端点、机会式集群利用，再加**智能体化作业编排**：作业启动从 **30–60 分钟降到约 5 分钟**。嵌入侧 **4096 维 / 64K IVF 分区 / 数百亿行** 级别的语义检索，是"长尾挖掘 + 近重复剔除"能跑起来的原因（全译 716）。

**5.2 训练侧**（数字都来自主体句，可直接 grep）：

| 优化 | 收益 | 位置 |
|---|---|---|
| rank 同步的流选择（全局种子选择器让各 rank 打包结果一致） | **+54%** 端到端吞吐 | 全译 782 |
| 前瞻打包（放不下的小样本暂存 lookaside，末尾按原序塞回） | 有效序列长度 **+8%** | 全译 786 |
| 双向扁平注意力（把 AR/DM 两条掩码拼成一张图，一次算完） | **+22%** | 全译 817 |
| 选择性激活重计算 SAC（只重算激活小、重算便宜的张量） | **+13%**；全量重计算罚 **≈33%** | 全译 847 |
| tokenizer 分块编码（256p 一次 68 帧 / 480p 24 / 720p 12） | 把 GPU 推到 roofline 计算受限侧 | 全译 863 |
| torch.compile + **AOTInductor 分片编译 45 张静态图** | 编码延迟再降 **52%**；启动 **15 分钟 → <1 分钟** | 全译 867 |
| 异步 checkpoint（Gloo 进程组写、保存计划记忆化） | 端到端省 **4%（Nano）/ 9%（Super）**；开销再降约 **60%** | 全译 881 |

**5.2.8 吞吐实测（GB200，稳态单卡）**：

| 模型 | 单步 | 迭代/小时 | 图像 token/GPU·h | 视频 token/GPU·h | TFLOPS | MFU |
|---|---|---|---|---|---|---|
| Nano | 7.1 s | **507** | 4.56M | 16.23M | 520 | 0.23 |
| Super | 19.5 s | **185** | 1.66M | 5.91M | **673** | **0.30** |

读法：Nano 刷 token 吞吐，Super 刷算术利用率——**越大越"喂得饱"卡**，这是双塔+长上下文模型的典型现象。

**5.3 服务侧（全译 924–1009）**：参考实现是"权威规格"，生产侧 Reasoner 走 **vLLM / TensorRT-LLM**（复用上游 Qwen3-VL 支持），Generator 走 **vLLM-Omni**，另有 NIM。原生 PyTorch 路径的加速手段：**层粒度 CUDA Graph + torch.compile(reduce-overhead)**（文生图 **30–60%**）、CFG 并行（两个 forward 合批）、Reasoner 塔缓存（AR 前缀只算一次，正好是 §2.3 非对称掩码送的红利）、256p 批处理 **8–55%** 增益（480p/720p 因 74k 上下文只容 1 条而失效）。

### 8.3 五个最容易读错的地方

1. **把 MoT 当 MoE**。没有 router，没有 top-k；是按 token 类型硬分派的两套参数。
2. **把"统一"理解成省算力**。省的是 AR 前缀重复计算与数据/流水线割裂，**不省参数量与显存**（两塔双份）。

4. **把 39.7% 当"通用机器人能力"**。它是 DROID 后训练 + RoboLab-120 specific 设置、10 次 rollout 的结果。
5. **借 VAE 白嫖**。Wan2.2 免掉了自研 tokenizer，但 §5.2.6 的整节工程（68/24/12 分块、45 图 AOT 预编译、52% 延迟）就是它的账单。
